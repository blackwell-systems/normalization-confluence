\section{Method}\label{app:method}

\paragraph{Names as statements.} Every result cited in the paper is a \texttt{Theorem}, \texttt{Lemma}
or \texttt{Corollary} in the development, cited by its Coq name. Each statement in the paper was read
from the Coq source; a script checks that every name cited on the atlas and the website is declared
and gated, and that the counts shown there equal the gate.

\paragraph{The gate.} \texttt{coq/verify.sh} runs \texttt{Print Assumptions} on every gated result and
fails if any depends on an axiom or an admitted proof, or if the number of gated results falls below
the threshold. Nothing in the development is admitted.

\paragraph{The freeze.} For the tests of \cref{sec:tests}, the eight kernel files were frozen: their
SHA-256 hashes are recorded in \texttt{research/predictions/frozen.sha256}, and the same script fails
if any of them changes. Outside recoveries and predictions are new files only.

\paragraph{Predictions.} A prediction is committed as a file, unchanged after the commit that adds it,
before any test; the commit is its timestamp. Candidates that were refuted before commitment are kept in
\texttt{research/predictions/candidates.md}.

\section{The committed predictions}\label{app:predictions}

The claims below are copied from the committed files, \texttt{research/predictions/P2.md} and
\texttt{P3.md}, with the Markdown removed.

\paragraph{P2 (committed 2026-10-11, commit \texttt{ba043e9}).} \emph{Model.} The marriage market with
$n$ men and $n$ women and complete strict preferences; states are matchings (partial allowed); labels
are the $n^2$ pairs; the update for $(m, w)$ matches $m$ with $w$ if $(m, w)$ blocks the matching,
meaning each is single or prefers the other to the current partner, and their former partners become
single; otherwise it changes nothing. A fair schedule names every pair infinitely often, naming a
non-blocking pair being a no-op. \emph{Claim.} There are $n \le 4$, preferences with exactly one stable
matching, and a start matching from which a bad fair lasso exists: a pair-word reaches a matching, and a
nonempty pair-word that names every one of the $n^2$ pairs returns it to itself, with some loop state
unstable. \emph{Pass.} An explicit instance, its unique stable matching and a bad fair lasso, all
mechanized. \emph{Fail.} An exhaustive check, up to symmetry, showing that for every $n \le 4$ and every
profile with exactly one stable matching there is no bad fair lasso from any start. \emph{Probability
stated:} about 0.6. \emph{Outcome:} passed (\cref{sec:tests-predictions}).

\paragraph{P3 (committed 2026-10-11, commit \texttt{aaba8b4}).} \emph{Setting.} One document with
revisions 1-a, 2-b, 3-c and 4-d, where 4-d is a deletion; each revision delivered once with its full
history, one per request, to a fresh database with \texttt{revs\_limit} 3, in each of the 24 orders;
CouchDB~3.5.3 and PouchDB~9.0.0. \emph{Claims, each scored separately.} (1) CouchDB with default
settings: the document ends live, with winning revision 1-a, on exactly the 6 orders in which 1-a is
delivered last, and deleted on the other 18. (2) CouchDB with \texttt{stem\_interactive\_updates =
false}, then compaction: deleted on all 24 orders. (3) PouchDB with default settings: live on exactly
the 12 orders in which 1-a is delivered after 4-d, and deleted on the other 12. \emph{Pass and fail.}
Each order is run three times in a fresh database; a claim passes if every scored order matches the
computed table and fails on any reproducible mismatch. \emph{Probability stated:} about 0.75.
\emph{Outcome:} passed on all three claims; the packaging deviation (a Homebrew build of the same
version instead of the official image) is recorded in the outcome.
