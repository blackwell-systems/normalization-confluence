# Gap 3, three tokens: SAT decision, transition statistics, candidate orders, and the obstruction

Date: 2026-10-05. Setting and notation as in `REPORT.md` and `K2.md`: Boolean networks, (A) is no
cycle in any local graph G(x), (B) is out-degree at most one in every G(x). A token is an unstable
vertex; under (B) with no self-loops the token count never increases (`ucnt_mono`), so it is
constant on a closed asynchronous run. p is the unique fixed point, D(x) = x xor p, and a token at
v is good if v is in D(x), bad otherwise. g and b count the good and bad tokens.

**Question.** Under (A)+(B), is there a closed asynchronous run whose states all have exactly three
unstable vertices?

**Result.** Not proved. No such run exists for n = 3 to 6 (SAT, two encodings of (A), two
solvers); n = 7 was still running at the time of writing. One and two tokens are proved for every n
(`one_token_closed`, `two_token_closed`). Gap 3 stays open. Nothing in this file is in the
axiom-free gate.

## 1. SAT decision for k = 3

`run_k3.py n opts solver` is `run_k2.py` with "exactly K unstable vertices" at every state of the
closed run (K = 3 by default, `k=<K>` to change it). Sound strengthenings, as in `run_k2.py`:
- `sym`: a state of the run is 0 and its chosen edge flips vertex 0 (translation and permutation
  symmetry).
- `tok`: every chosen edge passes a token (implied by "exactly 3" at both ends; kept as a hint).
- `alldir`: every vertex is flipped on some chosen edge. Sound because every smaller n is decided
  and k <= 2 is proved. A closed run that flips only the vertices in I is a closed run of the
  subcube network on I, which keeps (A) and (B). Its token count inside I is constant (`ucnt_mono`)
  and at most 3: fewer than 3 is excluded by `one_token_closed` and `two_token_closed`, exactly 3
  on fewer vertices by the smaller-n decision.
- `rank`: (A) by a ranking of each G(x) (order encoding) instead of one clause per elementary
  cycle; under (B) both say that each G(x) is acyclic.

Encoding check (`noA`: (A) replaced by "no self-loops"): SAT at once (0.0 s) for n = 4, 5, 6 and 7
with both solvers. Every witness passes `verify.py`: (B) holds, (A) fails, and the asynchronous
state graph is cyclic. At n = 3 the query is UNSAT even without (A), because three tokens on three
vertices leave no stable receiver.

| n | Options | CaDiCaL 1.9.5 | Glucose 4 |
|---|---|---|---|
| 3, 4, 5 | sym, tok, alldir (cycle clauses / rank) | UNSAT, <= 0.1 s | UNSAT, <= 0.1 s |
| 6 | sym, tok, alldir | UNSAT, 11.6 s | UNSAT, 15.9 s |
| 6 | sym, tok, alldir, rank | UNSAT, 13.0 s | UNSAT, 18.3 s |
| 7 | sym, tok, alldir | running at the time of writing (over 1 h) | running (over 1 h) |
| 7 | sym, tok, alldir, rank | running (over 1 h) | running (over 1 h) |

(The n = 6 times are from a lightly loaded run; the logged rerun in `k3_n3to6.log` took 20 to 34 s
under heavy load. n = 8 was not attempted: n = 7 already runs far longer than for k = 2.) Breaking
symmetry through the fixed point instead (`psym`: f(0) = 0, with the implied `pbad`) is sound but
slower (47 s at n = 6), so it is not used for n = 7.

Largest n decided for k = 3: 6. The four n = 7 runs were still running at the
time of writing, on a heavily loaded machine; for comparison, k = 2 at n = 7 took 3 to 5 minutes
(K2.md). A follow-up records their result.

## 2. Proved structural facts (all k unless stated)

These hold for every n, with short proofs; each was also checked exhaustively by SAT for small n
and on every sampled network (`check3.py`, `fals_f12.py`, `commute3.py`), with no exception. F1,
F2, C1 and C2 are the most promising lemmas for a proof (section 5 (b) names the one that is
missing). F1 for every k is being mechanized separately (`coq/LocalTokenBalance.v`, `bad_le_good`);
F2 and C1 are not mechanized.

- **F1, b <= g at every state.** F(x) differs from x exactly at the tokens; a good token flips
  toward p and a bad one away, so d(F x, p) = d(x, p) - g + b, and non-expansiveness with F(p) = p
  gives b <= g. For k = 2 this is `not_both_bad`; for k = 3 every 3-token state is (g, b) = (3, 0)
  or (2, 1). Exhaustive SAT for k = 3 (`fals_f12.py`): no state with two bad tokens, n = 3 to 7.
- **F3, slack bookkeeping.** On any descending path from x to p (flipping the vertices of D(x) one
  at a time), (number of flips with no out-arc) + 2 (number of flips whose out-arc leaves the
  current F xor p) = g - b. (Each flip changes F in at most one coordinate, F xor p goes from size
  d - g + b to 0 in d steps.)
- **F2, near-rigidity at (2, 1).** With slack g - b = 1, the first step of a descending path is
  never an "up" step, so every vertex of D(x) points into M = F(x) xor p = (D(x) minus the good
  tokens) plus the bad token, or nowhere. In particular no vertex of D(x) points at a good token.
  (For k = 2 the slack is 0 and this becomes `tight_arc`, which with (A) gives `head_arc`; for
  k = 3 the bad token itself is unconstrained.) Exhaustive SAT: holds for n = 3 to 7.
- **F4, square rule.** If v passes its token to w (v -> w in G(x), w stable), then at flip v x the
  out-arcs of v and of w are unchanged, and any other vertex changes its out-arc only if w is its
  old or its new target. (From (B) at x, flip v x, flip j x and flip j flip v x.)
- **F5, transfer rule.** Since f_j does not depend on x_j, an arc u -> j exists at x iff it exists
  at flip j x. So arcs into the fired vertex are kept, and an arc into w is never redirected to v.
- **F6.** The out-path of the receiver w is the same at x and at flip v x (F4 plus (A)).
- **C1, critical pairs.** Two consecutive moves of a closed run, (v1 -> w1) from x then
  (v2 -> w2), can be swapped (v2 then v1 from x, three tokens throughout) iff v2 != w1 and
  w2 != v1. Proof: v2 is unstable at x iff v2 != w1; by F5, v1 stays unstable after v2 iff
  w2 != v1; `ucnt_mono` gives the intermediate count. So the only critical pairs are "the same
  token moves twice" and "follow": the second token moves into the vertex the first one just
  left (it pointed straight at the first token). `commute3.py`: 57,442 sampled pairs, no
  exception (9,630 same-token, 11,057 follow).
- **C2.** At every 3-token state some order of the three tokens fires each once, each still
  unstable when fired, and so reaches F(x) (25,036 sampled states, no exception).
- **Token set determines the state.** Under (A) alone, x -> x xor F(x) is a bijection: for any c,
  F xor c has the same local graphs, so by Shih and Dong it has exactly one fixed point. (Checked on
  every sampled network.) So "walks that return the tokens to the same vertices" only return to the
  same state, and episode orders of that form are vacuous (section 4).

## 3. Transition statistics

Samples: `sample3.py` asks SAT for an (A)+(B) network together with a symbolic walk of L moves
(one state per step, no repeated state) whose states all have exactly three tokens, with random
phases. This avoids the near-constant networks of a plain random-phase sampler (K2.md, section 2).
Sets: n = 4 (L = 3, all 384 networks), n = 5 (L = 4 and 6, 800), n = 6 (L = 3 and 6, 600),
n = 7 (L = 6, 100). Every one of the 1,884 networks passes `verify.py` ((A), (B), acyclic state
graph). Longest 3-token walk: 3 at n = 4, 6 at n = 5, 9 at n = 6, 12 at n = 7. `stats3.py`
classifies every count-preserving move between 3-token states of these networks: 31,490 moves.

| (g, b) before | fired | receiver | (g, b) after | n = 4 | n = 5 | n = 6 | n = 7 |
|---|---|---|---|---|---|---|---|
| (2, 1) | bad | bad | (2, 1) | 384 | 2,259 | 1,775 | 619 |
| (2, 1) | good | good | (2, 1) | 768 | 4,789 | 4,391 | 1,720 |
| (2, 1) | bad | good | (3, 0) | 0 | 291 | 687 | 397 |
| (3, 0) | good | bad | (2, 1) | 0 | 641 | 2,877 | 926 |
| (3, 0) | good | good | (3, 0) | 0 | 1,209 | 5,777 | 1,980 |

There is no (2, 1) good -> bad move (it would make (1, 2), against F1), so d rises only on
bad-token moves, and g changes only on bad -> good (+1) and good -> bad (-1) moves.

Relations among the three token vertices (n = 5 to 7, 30,338 moves):
- **Token-to-token arcs at x:** none on 13,083 moves, one on 14,478, two on 2,777. The fired
  token never points at a token (that would be a collision and drop the count).
- **Another token points straight at the fired vertex:** 9,670 moves. This is the "follow"
  critical pair of C1: that token can then move into the vacated vertex.
- **At the (2, 1) states of the samples (n = 4 to 7, 16,553 states):** the bad token points at a good token at 8,213 of them (the k = 2
  swap "good then bad" fails there), and a good token points at the bad one at 10,566 (so "bad
  then good" fails).
- **Collision case (two tokens share the receiver w):** 7,934 moves. After the move the sharer
  points at w (token-to-token) on 2,675, is redirected to another vertex on 3,534, and loses its
  out-arc on 1,725. The redirection to another vertex ("diversion") is what lets a reach set grow
  (section 4).
- **Shape of the relation:** at (2, 1) states on long walks, the three tokens usually lie on one
  out-path (each pair in ancestor relation), and the shape cycles through "bad -> good -> ...",
  "good -> bad", "bad -> stable" patterns as in the most frequent transitions printed by
  `stats3.py`. At n = 4 every count-preserving move is of this kind.

## 4. Candidate orders and how each fails

`mine3.py` counts, for every count-preserving 3-token move, whether a candidate falls, stays or
rises (n = 4 to 7, 31,490 moves). A candidate has to fall on every move, or never rise and fall
on every closed run.

| Candidate | Rises on | Outcome |
|---|---|---|
| d(x, p) | bad -> bad (5,037), bad -> good (1,375) | fails |
| g, -g | bad -> good, good -> bad respectively | fails |
| lex (g, d), (d, -g), (-g, d) | bad moves; (-g, d) also good -> bad | fails |
| d + d(F x, p) = 2d - g + b | bad -> bad (5,037) only | fails; this is the bookkeeping potential, flat on type changes |
| lex (#good, relation shape, d) | its first component already rises on bad -> good (1,375) | fails |
| synchronous time to p, sum of synchronous distances, the distance vector, the kappa vector d(F^j x, F^(j+1) x) | all four move classes (e.g. sync time: 4,219 moves) | fails |
| token depths (multiset, sum), token heights (multiset, sum), bad-token depth, good depths | all four classes | fails |
| reach set size (union of token out-paths) | never at n <= 5; 169 moves at n = 6 and 285 at n = 7 (shared-receiver diversion) | fails |
| token-to-token arc count, lex (-g, t2t, d) | all classes | fails |
| episode "d falls between consecutive visits to (3, 0) states" | `episode.py e30`: SAT at n = 6 with a 4-move walk ggg, gbg, gbg, bgg, ggg and d = 4, 3, 4, 3, 4 (checked by `verify.py`); UNSAT at n = 5 for L <= 8 | fails |
| episode "d falls when the tokens return to the same vertices" (with or without types) | UNSAT for n <= 6, L <= 8, but vacuous: the token set determines the state (section 2) | gives nothing for closed runs |

Abstract (state-free) orders, tested in the forest-plus-token game of section 5: free path
lengths (sum, multiset), union of free paths, ancestor counts, vertices with a token at or below,
depth sums, number of blocked tokens and their lexicographic combinations all rise on some game
move at n = 5 (`gamepot.py`); an LP over 20 such features finds small-n weights (`gamelp.py`)
that do not survive n = 6, where the game has a cycle.

## 5. The precise obstruction

**(a) Type changes break the k = 2 machinery.** For k = 2, F1 gives one good and one bad token
with slack 0 (`tight`), so every vertex of D points into D plus the bad token, the bad token never
points into D (`head_arc`), and the token types are invariant. For k = 3 the (2, 1) slack is 1:
F2 still constrains every vertex of D, but not the bad token, which can pass to a good receiver
(the n = 4 witness of K2.md; 1,375 sampled moves), so g rises and falls on a single walk.

**(b) History normalization needs rate balance.** By C1 the only critical pairs are "same token"
and "follow", and both are compatible with synchronous rounds (in a round, the leader moves first
and then the follower moves into the vacated vertex). C2 says each round can be realized by single
firings. Commutation preserves each token's (particle's) number of moves. So a closed run can be
normalized into F^h, which `sync_orbit_fixed` excludes, only if every particle makes the same
number of moves per period, with followers never lagging their leader by two or more rounds. For
k = 2 this rate balance is exactly what type invariance plus #T = #H gives (`W_dp`, `W_sort`,
`W_main`). For k = 3 the balance "#good firings = #bad firings" (d returns) mixes particles,
because a particle changes type, and nothing found here forces per-particle balance. If the
particle permutation of the period is a 3-cycle, balance holds over three periods; for the
identity or a transposition it is open. The missing lemma is therefore:

> **Rate balance (open).** On a closed asynchronous run with exactly three tokens, under (A)+(B),
> every token makes the same number of moves per period, and at every "follow" pair the follower
> has made at least as many moves as the leader.

With it, C1 and C2 normalize the run into rounds and `sync_orbit_fixed` closes the case, uniformly
in k.

**(c) No proof from local rules alone.** Exploratory SAT (n <= 5, k = 2 and 3, all UNSAT; not
part of the decision above) shows how little of (A) and (B) the claim uses:
- the fixed point is not needed: (A) only at the states of the run, with (B) everywhere and no
  self-loops (`run_k3.py ... Aon`), already excludes the run;
- of (A), only "the fired vertex lies on no local cycle at its firing state" is needed
  (`avar.py fired`), while forbidding only 2-cycles, only cycles of length >= 3, only cycles
  avoiding the tokens, or only cycles through two tokens is SAT (`avar.py`); forbidding only one
  sign of local cycle is SAT for k >= 2 (`signvar.py`);
- (A) at one state of the run is not enough (`Aone`, SAT at n = 5 for k = 3);
- (B) is needed at the run states and their cube neighbours (`localB.py nbr`); (B) at the run
  states alone is SAT at n = 5.
That suggests a combinatorial proof on the sequence of local forests. The natural relaxation is
`game.py`: a forest plus a token set, moves by the square rule F4 refined by F5, (A) at every
configuration. It is acyclic for n <= 5 (every K) and for n = 6, K = 2, but at n = 6, K = 3 it has
a 9-move cycle (`gamecyc.py`):

```
((2,-1,1,-1,5,3), {0,3,5}) fire 0   ((2,-1,1,2,2,2), {2,3,5}) fire 2
((2,-1,1,2,2,2), {1,3,5}) fire 3    ((-1,-1,1,2,0,4), {1,2,5}) fire 5
((-1,4,4,4,0,4), {1,2,4}) fire 4    ((-1,4,4,4,0,4), {0,1,2}) fire 1
((-1,4,5,-1,0,3), {0,2,4}) fire 2   ((5,5,5,-1,5,3), {0,4,5}) fire 5
((5,5,5,-1,5,3), {0,3,4}) fire 4
```

(o[j] is the out-neighbour of j, -1 for none.) No network realizes it (`realize.py`): a 4-move
prefix is already UNSAT, with a minimal core of 9 constraints (`core.py`). They are the out-arcs
of the four fired vertices, of vertices 3 and 5 at the start, of 2 at the end, and (B) at two
cube neighbours. The core is a geodesic argument over four flips: from x0 = 0 the run flips
0, 2, 3, 5 and F changes by e1 + e4. Along the other geodesic 3, 5, 0, 2, vertex 3 has no
out-arc, 5 -> 3 transfers to the neighbour by F5, and the last flip changes e4, so the third
flip would have to change two coordinates against (B). So any k = 3 proof has to use
non-expansiveness across geodesics of length at least four, as F2 (a statement about every
descending path to p) does. Rules on single squares do not suffice.

**(d) A box argument does not apply.** Every sampled network has nested subcubes
X_(i+1) = hull F(X_i) shrinking to {p}, which with a subnetwork induction would exclude every
cycle (Bertsekas-style). But (A)+(B) networks with no constant coordinate exist from n = 5
(`noconst.py`), so the box iteration can stall at the full cube.
